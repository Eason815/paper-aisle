## Memory-R1: Enhancing Large Language Model Agents to Manage and Utilize Memories via Reinforcement Learning

让Agent学会哪些记忆该新增、更新或删除。

- 原文：https://aclanthology.org/2026.acl-long.583/
- 问题：Q03；来源层级：Abstract；轨道：main
- 为什么占一个名额：相较Sculptor主动整理上下文和经验记忆质量分析，本篇补充通过任务结果学习外部记忆操作的路线。

**问题**：外部记忆库能补充有限上下文，但静态规则未必知道该保存、更新或删除什么，也未必能把检索结果有效用于推理。

**发现**：论文报告：Memory-R1在LoCoMo、MSC和LongMemEval等记忆测试中优于所比较基线，并展示跨问题类型与模型规模的适用性；这不等于已验证真实工具执行效果。

**做法**：设置记忆管理与回答两个角色：前者学习新增、更新、删除或不操作，后者筛选相关条目并推理；使用结果驱动的强化学习训练两者。

图解：记忆管理与回答两个角色
- 管理记忆：学习新增、更新、删除或不操作等结构化记忆动作。
- 利用记忆：筛选相关条目并据此推理回答。
- 结果驱动训练：使用任务结果的强化学习训练两个角色。

待核读：需核读训练样本、奖励、基线与数据划分；摘要的问答收益不能直接外推到行动任务。

## Mem2ActBench: A Benchmark for Evaluating Long-Term Memory Utilization in Task-Oriented Autonomous Agents

能回答旧信息，不代表能用记忆选对工具和参数。

- 原文：https://aclanthology.org/2026.acl-long.370/
- 问题：Q03；来源层级：Abstract；轨道：main
- 为什么占一个名额：补充Q03的行动型评测边界，与Memory-R1的记忆问答训练对照：记住或答对不自动代表会行动。

**问题**：现有记忆测试常要求回答明确提出的事实问题，难以判断Agent是否会在没有显式提醒时，把旧偏好和任务状态用于工具执行。

**发现**：论文报告：在其工具使用测试中，所测记忆框架仍难以主动利用记忆确定调用参数；结论限定于该基准及所比较系统。

**做法**：合并工具与对话来源，进行一致性处理，构造长期交互记忆链，再反向生成依赖这些记忆的工具任务，检查工具选择与参数依据。

待核读：需核读任务生成、记忆依赖性的人工检查和判分方式，判断是否能区分检索失败与使用失败。

## CostBench: Evaluating Multi-Turn Cost-Optimal Planning and Adaptation in Dynamic Environments for LLM Tool-Use Agents

工具失效或价格变化后，原计划还划算吗？

- 原文：https://aclanthology.org/2026.acl-long.584/
- 问题：Q01；来源层级：Abstract；轨道：main
- 为什么占一个名额：相较ToolTree的搜索方法和LongHorizonUI的界面执行，本篇补充环境变化与成本约束这一评测切面。

**问题**：只评任务完成会忽略资源消耗；静态设置也看不出工具失效、费用变化以后，Agent能否及时调整原计划。

**发现**：论文报告：所测模型在其旅行规划任务中难以稳定找到成本最优解，动态变化进一步影响表现；不能由此判断真实出行效果。

**做法**：在旅行规划环境中组合不同成本的原子和复合工具，并引入工具故障、费用变化等阻断事件，比较静态规划与动态适应。

待核读：需核读最优计划的求解与验证、动态事件设计，以及模型工具预算是否公平。

## Why Do LLM-based Web Agents Fail? A Hierarchical Planning Perspective

长任务失败，问题可能在执行，而不只在计划。

- 原文：https://aclanthology.org/2026.acl-long.1483/
- 问题：Q05；来源层级：Abstract；轨道：main
- 为什么占一个名额：补充失败归因的非训练分析路线；与AgenTracer学习诊断、Fission-GRPO学习恢复形成不同层次的比较。

**问题**：端到端成功率只告诉我们任务是否完成，难以判断是目标分解有问题、页面操作落地失败，还是出错后没有正确调整。

**发现**：论文报告：所测设置中，结构化计划比自然语言计划更简洁且面向目标，但底层执行仍是主要瓶颈；不能据此概括所有Web Agent。

**做法**：用分层规划框架分别分析高层计划、底层执行和重新规划，并比较规划领域定义语言PDDL与自然语言表示，观察推理、落地与恢复。

图解：把失败拆到三个层次
- 高层规划：检查目标与步骤组织是否合理。
- 底层执行：检查行动能否在页面上正确落地。
- 重新规划：检查反馈出现后能否调整后续行动。

待核读：需核读模型、环境、错误归因协议及底层执行瓶颈的证据，避免把单一测试结论当成普遍规律。

## ToolOmni: Enabling Open-World Tool Use via Agentic learning with Proactive Retrieval and Grounded Execution

工具库不断变大和变化，Agent怎样找到并用对新工具？

- 原文：https://aclanthology.org/2026.acl-long.1736/
- 问题：Q02；来源层级：Abstract；轨道：main
- 为什么占一个名额：相较OctoTools的工具组织、ToolACE-MT的数据生成，本篇补充大规模变化工具库的检索与泛化路线。

**问题**：固定的向量检索可能不能对齐用户意图与工具语义，把工具记进模型参数又难以适应未见工具，导致检索与执行之间脱节。

**发现**：论文报告：ToolOmni在所测开放工具设置中改善检索和执行，并展示未见工具相关的泛化收益；具体划分、对照预算与提升幅度仍待核读。

**做法**：先用多轮交互数据进行监督微调，再以解耦多目标GRPO强化学习同时优化工具检索和执行，把主动检索与执行纳入推理循环。

待核读：需核读未见工具划分、检索候选规模、工具描述泄漏和同预算比较，不能仅凭摘要的领先表述下结论。

## SafeMCP: Proactive Power Regulation for LLM Agent Defense via Environment-Grounded Look-Ahead Reasoning

在Agent拿到危险工具能力之前，先评估后续风险。

- 原文：https://aclanthology.org/2026.acl-long.522/
- 问题：Q08；来源层级：Abstract；轨道：main
- 为什么占一个名额：首批Q08侧重停止与上下文省略，本篇补充服务端工具获取控制，扩展安全边界而非增加同类成功率案例。

**问题**：更多工具扩大了Agent能影响的环境范围，也可能把小错误放大；只在危险行动发生后检查，可能无法及时约束能力扩张。

**发现**：论文报告：SafeMCP在PowerSeeking Bench、ToolEmu和AgentHarm等测试中降低风险并保留任务效用；不同任务与部署条件下的取舍仍需核查。

**做法**：在服务端使用内部世界模型做前瞻推理，通过主动工具过滤约束危险能力获取，并以即时干预兜底；训练包含环境动态学习、安全策略初始化和强化学习。

图解：前瞻过滤与即时干预
- 前瞻风险推理：内部世界模型推演工具能力可能带来的后续安全风险。
- 主动工具过滤：限制危险工具能力的获取与扩张。
- 即时干预兜底：以即时干预作为另一层保护。

待核读：需核读风险定义、世界模型误差、漏拦与误拦，以及安全收益对应的效用损失。

页面里看见的文字，也可能把Agent带离用户目标。

- 原文：https://proceedings.iclr.cc/paper_files/paper/2026/hash/28e4c3696637ac727051a2922643ec6a-Abstract-Conference.html
- 问题：Q08；来源层级：Abstract；轨道：main

**发现**：论文报告：所测电脑与浏览器Agent在部分平台上会被视觉注入误导，现有防御改进有限；攻击成功率依赖平台、模型和威胁设置。

**做法**：定义从视觉内容注入到越权结果的端到端威胁模型，在多个交互平台的真实运行环境中构造测试案例，检查Agent与防御方法的表现。

待核读：需核读攻击者控制范围、成功判据和防御预算，不能把特定平台比例外推为日常使用风险。

## De-Linearizing Agent Traces: Bayesian Inference of Latent Partial Orders for Efficient Execution

历史执行顺序里，哪些步骤必须先做，哪些可以并行？

- 原文：https://icml.cc/virtual/2026/poster/63737
- 问题：Q01；来源层级：Abstract；轨道：unknown
- 为什么占一个名额：相较ToolTree在线搜索下一步，本篇从旧轨迹学习可复用依赖，补充规划结构复用与并行执行的路线。

**问题**：把成功轨迹当成固定顺序会隐藏可并行步骤，还可能让Agent反复为熟悉流程逐步推理，增加时间和调用开销。

**发现**：论文报告：BPOP在Cloud-IaC-6与WFCommons工作流中更准确恢复依赖结构，编译执行器减少了令牌与执行时间；其他任务适用性仍待验证。

**做法**：把线性轨迹看作潜在依赖图的一种合法排序，用贝叶斯方法推断偏序结构，再交由编译执行器利用该结构并裁剪无关上下文。

图解：由历史轨迹得到依赖计划
- 历史线性轨迹：将轨迹视为潜在依赖结构的某种合法执行顺序。
- 推断偏序依赖：用贝叶斯框架估计哪些动作具有先后约束。
- 编译执行：利用学得的依赖结构执行，并减少无关上下文。

待核读：该页具体轨道未知；需核读轨迹质量、依赖真值、结构恢复指标与并行执行是否保持正确性。

## AgentSlimming: Towards Efficient and Cost-Aware Multi-Agent Systems

多Agent系统里，哪些角色可以去掉或换成便宜模型？

- 原文：https://aclanthology.org/2026.acl-long.1387/
- 问题：Q06；来源层级：Abstract；轨道：main
- 为什么占一个名额：相较Grammar Search搜索协作结构，本篇从既有结构做压缩，补充“减少角色”与成本质量取舍，避免只收集扩张式方法。

**问题**：自动扩张协作结构可能留下冗余Agent并增加令牌消耗，手工设计又费力；更多角色不一定意味着更值得付出的成本。

**发现**：论文报告：AgentSlimming在所测工作流中显著降低令牌成本，表现变化较小且部分设置有所改善；收益和可接受损失依赖具体比较条件。

**做法**：先用混合机制估计各Agent的重要性，再删除冗余角色或替换为低成本角色，每次操作都通过相对基线的接受规则检查。

待核读：需核读重要性估计、接受阈值、搜索费用与任务分布，不能把压缩比例当成普遍可达的收益。
