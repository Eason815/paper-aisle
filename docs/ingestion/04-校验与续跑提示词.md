# 校验、续跑与定向更新

以下代码块可按场景直接发送。路径请替换为实际批次路径；不要把占位文字当事实写入数据。

## 一、独立校验（默认只读）

```text
请依据 docs/ingestion/01-入库标准.md，独立检查【实际批次目录】，暂不修改或合并数据。
读取同目录 research-batch.schema.json、guides.schema.json，实际网站schema及转换器。
按以下项目报告 pass / warning / fail / not-run，给出论文ID、字段和原因：
1. research与guides各自schema；ID非空、论文ID/证据ID批内唯一、无越界字段。
2. guides键能定位本批可导入记录，Q编号存在且与项目目录内容完全一致；图节点ID唯一。
3. 每个实际速读段落都有非空basis；引用来自本条evidence，supports包含该段落字段。
4. evidence URL/locator/时间来自实际材料；概念图标题、caption和每节点有证据映射。
   实际阅读源材料，确认语义支持，不因引用存在就判内容正确；没有源访问则标未核验。
5. 无标题级记录生成速读，无摘要级记录编造全文数值或细节；无伪造人工确认。
6. 与网站和所有已配置批次按ID/标题/来源核对重复和版本；同工作ID保持稳定。
7. 没有个人收藏、阅读状态、标签、便签或备份；未知信息没有被占位符硬填。
8. 导入兼容：每记录official和venue有效且有来源，输入中不能混入全文图解，
   无跨已配置批次重复ID，不用删旧批次或改datasetId解决冲突。
9. 可见性和发表统计分开：unknown轨道、人未确认、缺机构/展示形式/代码只警告，
   不要求用户逐篇手工复核，不擅自改为已核实或正式纳入。
10. 给出实际候选/可读/可导入/重复/跳过/未完成数量，清楚区分新增与更新。
不要执行data:import、Git提交或发布；未运行的机器和浏览器校验如实标not-run。
若建议修复，列出最小修订，不用重新写全部论文掩盖差异。
```

JSON Schema的Python检查示例（在项目根目录执行，环境须有Python和jsonschema；缺依赖不能声称校验已通过）：

```powershell
python -m jsonschema --instance 'data/incoming/batch-002/batch-002.research.json' 'docs/ingestion/research-batch.schema.json'
python -m jsonschema --instance 'data/incoming/batch-002/batch-002.guides.json' 'docs/ingestion/guides.schema.json'
```

这些命令仅演示结构校验，旧版CLI可能提示弃用；完整校验宜使用Python `Draft202012Validator` 加 `FormatChecker`，并另做上述跨字段与语义检查。不能把两个命令的成功当作证据/内容/链接可访问性均已通过。

## 二、中断后续跑

```text
继续【实际批次目录】的论文制作，按 docs/ingestion/02-批量入库主提示词.md 执行。
先读checkpoint、已有research/guides/checks与本次原始输入，核对路径、批次与任务范围。
沿用已保存的paper.id、evidence.id、Q目录及真实获取时间，不重新编号、不重写已完成内容。
先验证已完成项；只处理尚未完成或被明确标为失败待重试的候选。
不要因没有聊天历史声称无法继续，也不要只相信checkpoint里“已完成”就跳过损坏文件。
完成一篇就保存，更新待办和下一步，缓存可用时不重复下载。
轨道/机构/展示形式缺失不阻塞；来源受限有限重试，继续其余论文。
保留原mode和发布边界。checkpoint只是进度，不构成新的推送/部署授权；
除非本次我明确再次授权publish=true，否则本次不推送发布。
最后报告本次新增完成、累计完成、待办/失败数量及最新校验状态。
```

## 三、补充已入库论文，不重复建档

```text
按 docs/ingestion/01-入库标准.md 更新以下已有论文：【论文ID列表】。
先定位每篇在data/research-import.json中的唯一归属批次及相关guides。
保留paper.id、datasetId、既有人工确认和个人状态关联，不复制到新批次。
只修改本次有新证据支持的字段；已有证据和历史内容冲突时明确报告。
三段速读修改原aiSummary，网站quickRead由转换器投影，不能只在网站上单独改文案。
补充摘要级导读时同步guide与evidence映射，避免图文漂移。
全文级材料先独立保存并列出readSections，当前转换器来源定位未适配时不发布全文图解。
字段省略不会删除旧值；需要移除错误旧字段时列出具体删除建议和依据。
本次mode=prepare，默认不合并、不推送；交付逐字段前后差异、来源和校验结果。
```

## 四、检查清单与故障处理

| 问题 | 处理 |
|---|---|
| 只有标题/源页不可读 | 待办，不虚构速读；继续其他记录 |
| 轨道未知、机构/展示形式/代码缺失 | warning，允许摘要泛读 |
| 已配置批次重复ID | fail，改为更新唯一归属记录，不换ID绕过 |
| 相同ID不同标题、同标题不同ID | 暂停受影响合并，核查版本映射 |
| Q对象内容不同 | 不静默覆盖，提出目录修订建议 |
| 证据引用不存在/与内容不符 | fail，修正文案或补真实依据 |
| 图无法确认结构 | 去掉图、保留headline，在checks说明 |
| 全文导读被固定标Abstract | 不接入当前图解路径，不降低真实sourceLevel |
| schema/构建/浏览器不能运行 | 记录not-run及原因，不能报通过 |
| 机器检查通过但内容越界 | 仍然fail；结构合法不等于事实可靠 |

检查项通过后，prepare仍不会合并。import模式按主提示词运行 `data:preview → data:import → 最终schema检查 → npm run check → 幂等预览与界面验收`；发布需要独立的明确授权。
