# 选材与阅读标准 v1.2：先广泛扫描，再核读代表作

本规则采用用户2026-10-26确认的节奏：先完成约50～60篇摘要泛读，之后围绕2～3个重点问题核读约6～8篇代表作。30篇只检查问题地图、重复路线与缺口；50篇检查是否够用；有明确遗漏才补至最多70篇。AI制作数不是用户阅读数，不从收藏或阅读状态推断科研审核。

## 选材顺序

1. 来源核实：以2026 ACL、ICLR、ICML、NeurIPS官方单篇页/论文集为主，核对版本、年份、作者与实际轨道。未知轨道允许泛读，不能计为已核实主会。经典、综述、其他会议或预印本单列补充。
2. 相关性：核心贡献直接涉及Agent决策、行动、交互、学习或评测；问题写为具体问句。
3. 增量覆盖：与已有工作比较，明确新增的方法、场景、失败现象、评测边界或不同结论。不是因为某类数量少就机械补齐。
4. 摘要核对：实际读取原始Abstract。网页有Lay Summary时分别识别；不能把通俗摘要误标为正式Abstract。摘要不足以支持的数值、消融、实现和普遍结论不补写。
5. 去重与保存：核对稳定ID、来源别名与预印本/会议版；每篇保存选入或延后理由。延后不是低质量评价。

每个新增名额必须回答：**已有论文之外，它让我多理解了什么？** 在review.reason写增量与对照对象，在selection保存实际处理候选、延后项和未处理范围。不编造全量摘要扫描数。

CCF A类只帮助限定检索范围，不等于单篇质量已核实。引用量、机构、Oral、代码开放、AI导读完整度均不是质量保证，不按这些信号填满名额或设置推荐分。CCF目录说明：https://www.ccf.org.cn/Academic_Evaluation/By_category/ 。机构/展示信息如已真实存在可展示，但不用于本轮挑选依据。

## 泛读最低要求

用户看导读后打开原始摘要核对，尝试回答：研究什么问题、旧方法为什么不够、怎样处理、在哪种任务/环境验证、与已读工作有什么区别。摘要未说明的内容标为“摘要未说明”，不猜答案。

尚不能解释问题与做法，在便签记“未理解：具体疑问”，阅读状态可保持未读或在读；不新增第五种阅读状态，也不自动把AI已制作改为泛读。难懂公式和实现先留疑问，不要求逐篇全文精读。

未读/泛读/在读/已读表示个人进度；来源核实、候选、Core和代表作判断是另一层信息，禁止互相替代。

## 扫描完成后的代表作核读

先选2～3个问题，各核读2～3篇，合计约6～8篇；问题确定前保留不同方法、重要基线、分析/评测与反向证据，不只留报告提升的复杂方法。

核读至少检查：任务与主张是否对应；基线和模型/工具/计算预算是否可比；关键实验与消融支持什么；结论范围、失败案例及相反证据。没看到某项不等于作者没做，须写实际读取位置与限制。

沿用模板Core/Related/Edge和阅读优先级A/B/C，不建立质量总分。AI可建议，最终代表性、趋势和方向由用户及导师确认。阅读优先级A是Stage 02优先核读，与CCF A类无关，需填写真实Read First位置；未核读不得虚构章节/图表号。

现有待核读组合：Sculptor＋How Memory Management Impacts LLM Agents；Fission-GRPO＋AgenTracer；AgentSuite＋AgentLens。它们是比较入口，尚不是最终代表作或质量排名，具体兴趣与人类理解以真实阅读反馈为准。

## 阶段验收

- 约30篇：从真实记录生成问题覆盖、方法对照、重复路线与缺口；不以篇数宣布热点或方法胜负。
- 约50篇：检查能否解释主要问题与区别、是否覆盖不同路线和反向证据。用户理解未知时明确待反馈，不替用户判定已完成。
- 扫描后：核读6～8篇，为核心判断提供可定位证据，形成1～3个Stage 02候选。
- 导师checkpoint讨论分类、代表作遗漏、证据缺口和继续方向；未安排时明确待讨论。

网站维持现有问题分类、个人状态与简化阅读页，不新增“质量认证”、复杂分数或额外必填标签。全文核读当前仍独立交付，不能把全文证据伪装为Abstract进入网站。
