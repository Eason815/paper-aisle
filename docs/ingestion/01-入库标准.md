# 批量论文入库标准 v1.0

适用日期：2026-10-23。目标是让 Paper Aisle 成为可连续泛读、看图理解、比较与做笔记的入口，而非堆放完整摘要的目录。

## 1. 三层数据与唯一内容源

| 层 | 存放内容 | 禁止事项 |
|---|---|---|
| 调研主记录 `<batchId>.research.json` | 元数据、问题分类、证据、三段速读、材料范围 | 不混入用户阅读状态；不虚构人工确认 |
| 导读 `<batchId>.guides.json` | 以稳定论文 ID 为键的中文概述、类型、可选概念图 | 不自行维护另一版速读；不塞入未实现的 UI 字段 |
| 网站 `public/data/papers.json` | 转换器从前两层投影并增量合并 | 不用某个批次整体覆盖旧库；不更改现有 datasetId |

三段速读只维护在 `aiSummary`；转换器生成 `quickRead`。同一观点在卡片、详情、图解中不能相互矛盾。现有例子在 `data/batches/batch-001.research.json` 与 `data/guides/batch-001.json`，只是结构参考，不作为新论文的证据。

## 2. 来源、缺失与自动化

- 优先单篇会议/论文集原始页面、ACL Anthology、OpenReview、arXiv 或作者提供的原文。搜索摘要只作线索，必须实际读取对应正文/摘要才写内容。
- 元数据取自当前核对版本；发表年份与 arXiv 首次上传年份分开。保留原题名和可核实的完整作者顺序。作者机构按该论文记载，不按现单位补填，不把所有机构分给所有作者。
- 未知可选字段省略，不填“未知”“待补充”、空字符串或伪造 URL 来占位。只有标题的线索留待办，不制作三段速读、不导入泛读库。
- 每条证据有稳定且批内唯一 ID、URL、实际读取位置、支持字段和声明类别；能取得真实获取时间时记录。`fact`、`author_claim`、`judgment` 分开。短摘录仅为核查所需，不批量复制摘要或全文。
- 元数据冲突保留两方来源和差异；无法确认就省略冲突字段或隔离该记录，继续处理其他论文。403/验证码/登录限制不绕过；每来源有限重试（默认最多2次）并尝试一个可访问的原始替代来源，仍失败就记录。
- 轨道优先自动提取；一个来源没有明确提供时即可保留 `track=unknown`、`trackVerified=false`。不反复要求用户人工核实，不因未知轨道阻止摘要入库。未知项不算正式主会已核实样本。
- `presentationType` 是实际展示形式，`verification.track` 是发表轨道，两者不能互证。只记录官方实际标签；不假定每个会议都有 Oral/Spotlight/Poster，不由 Poster URL 推断展示形式，不生成“里程碑/精选”。
- 机构、展示形式、代码缺失不是失败。只在来源确有代码仓库链接时填 `links.code`；有代码链接不等于已经运行或可复现。

## 3. 内容深度与最低可读性

默认 `depth=abstract`：实际读取摘要、题名与元数据；`sourceLevel=abstract`。如果还读取了方法/实验相关章节，主记录必须如实为 `fulltext`，并在 `readSections` 列明实际范围；局部核读不是通读全文。

| 内容 | 默认要求 | 质量判断 |
|---|---|---|
| 具体研究问句 | 一句 | 描述该论文实际解决的可区分问题，不只重复Q标签 |
| 中文导读 `headline` | 一句，通常20–50字 | 让新手知道读它能理解什么；不是官方中文题名 |
| 问题 `problem` | 1–2句，通常40–100字 | 旧办法哪里不足，会带来什么后果 |
| 发现 `finding` | 有依据时1–2句，以“论文报告：”开头 | 谁在什么任务/条件下观察到什么；不足则省略 |
| 做法 `approach` | 有依据时1–2句 | 关键机制如何应对问题；不是模块名称的堆砌 |
| 研究问题/场景 | 有依据时填写 | 一个主Q，可有次Q；Web/代码/桌面等是场景 |
| 图解 | 有结构且比文字更易懂时制作 | 节点及关系均有依据；允许无图并说明原因 |

字数是编辑参考，不作为机械的 schema 门槛。不熟悉的缩写第一次出现时解释。不要用“提出新框架、效果显著、有重要意义”等通用句子填满界面。

只读摘要，不能编造实验配置、消融、精确流程、局限或提升数字。具体数值需实际核读设置与结果并保留模型/任务/对照/指标/预算口径，区分百分点与相对提升。未读到不等于论文没做。避免“首次、彻底解决、普遍适用、证实热点升温”等无依据结论。

详细方法、实验卡、术语表、任务案例、局限与论文原图属于有证据后再扩展的内容。当前网站没有独立的实验卡/术语表输入，不把这些内容擅塞进新字段并声称已经展示。全文补充任务先交付可追溯研究材料，确认适配后再入站。

## 4. 概念图规范

输入只有 `headline`、`kind` 与可选 `diagram`；详见 `guides.schema.json`。不要把最终网站的 `sources` 或 `sourceLevel` 放到 guide overlay，当前转换器会注入它们。

| 研究类型 `kind` | 图布局 | 可表达关系 | 不能暗示 |
|---|---|---|---|
| `method` | `flow` | 有依据的步骤，或按说明排列的角色分工 | 摘要未说明的精确调用次序或反馈环 |
| `analysis` | `study` | 改变条件—观察现象—结论范围 | 把相关性画成因果，或伪装成新算法 |
| `benchmark` | `flow`/`study`；真实配对设计可用`paired` | 任务构造、控制变量、观察指标/失败类型 | 所有评测都被强制画成“执行/停止” |

- 每图2–6个节点，通常3–4个；同图节点 ID 唯一，名称短，说明可独立读懂。不能为了满足2节点最低数编造结构。
- `caption` 必须说明“AI 概念示意，基于摘要”，并解释它是流程、角色关系或观察框架；不称原论文图，不冒充实验样本。
- 在 checks 报告中逐项建立 `headline`、图标题/说明、各节点到 evidence ID 的映射。事实依据与AI教学组织方式分开；没有结构依据时只保留 headline。
- 可以有“下一步应核读”的说明，但不能把推测的新模块放进图再加一句免责声明。
- 图解全部用当前原生 JSON 节点表达；不为每篇生成装饰性位图，不加入抓取的图像和大文件。

## 5. 分类、选取与人工状态

沿用项目 `questionCatalog` 原始对象，不能悄悄改Q编号含义、名称或问句。需要新增/调整时提出建议，确认后同步契约与配置。Agent 任务统一方向 Agent；使用 RL 训练的 Agent 不因此移出本轮。其他研究范围使用参数指定的方向和既有目录，不把 Agent 规则硬套所有领域。

优先覆盖不同问题、方法路线、分析/评测、简单基线与反向证据。不按机构、引用量或展示形式排名，不强制会议/问题等额。报告实际查看数量、未处理范围和选取偏差；目的性阅读池不能用于外推全领域占比或升温趋势。

新记录默认 `review.decision=candidate`，明显补充材料可用 `supplement`；AI建议放 `suggestedDecision` / `suggestedRole`。不得自行写 `included`、最终 `role`、`humanConfirmed=true`、`humanChecked=true` 或 `confirmedAt`，已有真实人工状态不得重置。已排除记录不能为了达数量改回候选。

这些调研状态与网站个人未读/在读/已读完全分开；AI处理不更改用户状态。默认不生成推荐分数和重点标记，不因 Oral 或机构设置重点。

## 6. 稳定 ID 与多批次规则

- 先查现有主表、网站 ID/标题/原始链接。已有工作沿用原 ID，不因换会议版、标题或批次重新编号；新ID依据实际持久标识，不用批内序号。
- 同一工作预印本与会议版先核查再合并；相似标题不能直接合并不同论文。
- **当前转换器不允许多个已配置批次重复包含同一 ID。** 已收录论文的补充信息更新其唯一归属批次；不复制进下一新批。用户希望多个阅读集合共用论文时保留一份主记录，需要另行维护集合关系，当前导入配置不能靠重复批次实现。
- 新批次配置追加到 `data/research-import.json.batches`，旧批次不能删掉或只保留最新批，否则旧调研论文可能被划入基础阅读。仅按用户要求更新默认集合；保留旧集合同一 ID。
- `datasetId`、历史论文及未涉及配置不变；同一 `datasetId` 保留个人状态关联。公共输入、输出、Git与部署产物都不包含个人备份。

## 7. 当前转换器兼容要求

1. 每条交给转换器的记录须有来源依据的 `paper.links.official`（可用实际arXiv单篇页）及 `paper.venue`。当前来源汇总循环还会读取被跳过的记录，因此无此链接的线索只留在 preview/checks 待办，不放进已配置输入。
2. 实际导入门槛：非 `excluded`、不是 `title` 深度、有证据、有 `aiSummary.problem`。不要求人工确认或轨道已知。发现/做法不足可以省略。缺少导读时可以导入，但需在报告说明。
3. 当前图解 `sources` 固定从 official 链接生成，locator 固定为 Abstract。**本版默认只把摘要级导读交给此转换器。全文级记录/图解先保留在未配置批次中；先修正来源定位能力，才可接入，不得把全文结论错标成Abstract，也不得降级真实材料深度。**
4. 同 ID 标题变化、相同规范化标题但 ID 不同、Q目录内容变化均会停止。先输出冲突映射，不通过改 ID 或伪造标题绕过。
5. 导入是字段合并，省略字段不等于删除旧值；删除错误字段须明确列出有依据的定向修订，不能声称省略后已清除。
6. `data:preview` 只是差异预览，不是完整 JSON Schema/证据校验；运行时 Zod 也不能证明来源真实性。

## 8. 完成定义与保存

每完成一篇就把完整记录、导读和进度保存成合法文件；每5篇更新批次级报告。下一会话从已保存内容续跑，不依赖聊天记忆。缓存保存URL/真实时间/实际抓取范围，条件允许时保存摘要快照和校验摘要，不写入首屏网站JSON。

批次交付包含 research、guides、从JSON生成的preview、checks与checkpoint。checkpoint记录已完成ID、候选待办、失败原因、下一步、输入文件及实际校验结果。状态只记实际完成，不预报token耗尽时间；Git提交不是每篇保存的前提，不自动推送。

以下问题阻止受影响记录入库：结构不合法、论文身份/版本冲突、证据引用断裂、内容无依据、ID重复、人工状态被伪造、私密数据混入。继续处理无冲突论文，不能静默丢记录。

以下只警告：未知轨道、缺机构/展示形式/代码、未人工确认、未做图、缺摘要未报告的发现。只剩标题或无真实来源的记录保留待办而不发布。

合并前完成 schema 与语义检查、导入差异预览；合并后运行 `npm run check`、核对原ID/旧论文/collection/Q关联、重跑预览确认幂等，并检查一篇普通导读、一篇有图导读和缺字段记录。无法运行的检查写“未运行”，不能宣称通过。写入前保存公开库与配置的可恢复副本或本地Git checkpoint。未经明确发布授权不推送。
