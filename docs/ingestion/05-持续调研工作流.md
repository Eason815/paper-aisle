# 持续调研工作流 v1.2

## 现在从哪里继续

各批次制作进度以research:status为准；个人阅读进度以本地私有记录为准，不写入公共库，也不等同于科研审核或全文阅读确认。没有笔记输入时按现有问题覆盖补充选材，不推测兴趣。

目标约60篇：30篇时整理问题地图与缺口，50篇时检查覆盖是否足够，只有实际遗漏才继续至最多70篇。数量不代替内容质量。按用户确认先完成约50～60篇摘要泛读，再围绕2～3个问题核读约6～8篇代表作；默认一批最多10篇。全文核读另开每次2～3篇任务，遵循[选材与阅读标准](07-选材与阅读标准.md)。

## 每次循环

1. 用户可先导出“本轮阅读笔记”，并保存完整阅读记录备份。笔记不是入库前提；没有反馈照常按覆盖选材。
2. Codex读取本目录标准、`data/research-workflow.json`、`data/research-progress.json`、实际批次、导入配置与未完成checkpoint。运行`npm run research:status`，发现未完成批次先核对已保存内容再续跑。
3. 从官方目录、原始论文及相关工作发现候选。先查重，再选择能补充方法、场景、分歧或评测边界的工作。每篇在review.reason说明为什么占一个阅读名额，以及相较已有工作新增的理解；详见07。
4. 实际读取摘要后制作research与guides。每篇完成即保存合法JSON；每5篇更新汇总。轨道、机构、展示形式和图解缺失不阻碍继续。
5. 二次对照原文检查速读和图解。结构检查不能替代语义核对；运行本批及跨批次通用校验，记录未核查项。
6. import模式追加配置后执行`research:validate → data:preview → data:import → research:sync → check → data:preview`。最后一次预览应无预期外新增或更新。
7. 实际检查默认调研列表与基础论文显示开关、新增论文、有图与无图导读、问题筛选、翻篇、对比及手机布局。用户已授权publish=true且检查通过后，只提交本次相关文件并推送main，不强推。
8. 打开线上默认调研列表和新增内容验证。提交推送成功只是部署触发，不代表上线成功。把部署检查保存到被忽略的`.research-local/deployments/`，避免为记录某次提交的发布结果再递归产生新提交。

## 文件及命令

| 文件/命令 | 用途 |
|---|---|
| `data/research-workflow.json` | 稳定的研究范围与目标；个人阅读进度另存本地私有目录 |
| `data/research-progress.json` | 从真实批次派生的制作进度、问题覆盖和待续跑任务 |
| `data/research-map.md` | 从批次派生的阅读池覆盖清单，不是热点排行 |
| `data/incoming/<batchId>/` | research、guides、selection、guide-evidence、preview、checks、checkpoint与验收结果 |
| `npm run research:validate` | 所有已配置批次的JSON Schema、跨字段、重复身份和网站投影检查 |
| `npm run research:status` | 只读查看当前制作覆盖及未完成任务 |
| `npm run research:sync` | 从实际输入重新生成进度与问题地图 |
| `npm run research:resume -- data/incoming/<batchId>` | 对照已保存主表检查checkpoint，列出完成、损坏和待处理项 |

候选选材记录包含实际查看数、选入/延后理由、剩余未处理范围。未选入不自动意味着质量较低。每条记录保持唯一归属批次；以后补充同一工作时更新原记录，不复制到新批。

机器检查覆盖格式、引用存在、supports映射、稳定身份、人工状态和隐私字段；它不能自动证明论文主张成立，也不能仅靠程序确认图与原文语义完全一致。仍由执行AI实际读来源并保存语义检查说明，用户不承担逐篇补全元数据的工作。

原始HTML/全文缓存放在`.research-local/`，用户笔记与备份放在`.research-private/`。二者不提交Git、不放public。当前无用户笔记输入，不生成私人复盘文件。人工作出状态若需要增加，应以用户明确逐篇确认与可追溯的既有记录为依据；不能用“读完”自动填humanConfirmed。

checkpoint只保存任务进度和上次参数，不产生新的发布授权。用户当前指令的明确授权与限制优先；恢复任务不要求重复授权本次已经授权的操作。

```text
先核查未完成批次并续跑；没有才创建下一个未占用编号。
允许从官方目录、原始论文及相关工作发现候选；按覆盖与我提供的阅读反馈，

```

## 阶段检查点

- 约30篇：比较每类有哪些路线、哪些问题仍只有一个例子；从真实笔记总结疑问。没有可比证据时不做方法胜负排名。
- 约50篇：检查主要问题是否能用自己的话解释、是否有不同路线与反向证据；够用可结束Stage 01。
- 约60篇：扫描完成后先核读代表作，再形成有实验证据的报告与1～3个Stage 02候选；有实际遗漏才扩至70篇，不因目标篇数而虚构趋势。
- 摘要级分布可标为“AI初筛的目的性阅读样本”；汇报中的关键结论与少数代表作再核读原文。未知轨道不用于正式主会统计。

当前全文导读的来源定位仍有兼容限制，保持独立交付，不能把全文结论错标Abstract。

## 页面简化（用户确认）

页面移除“今天，从这一组开始”和全部批次切换。基础阅读集合默认隐藏，在筛选中可勾选“显示基础论文”；保留所有论文与个人记录。批次仅为制作、去重、续跑与审计元数据；makeDefault字段保留兼容，不影响阅读范围。阅读状态支持未读、泛读、在读、已读；推荐排序优先未读，AI入库不改动用户状态。
