# 当批参数与调用示例

主提示词负责固定规则，本文件负责可变输入。每次不必重写整套指令。下例批次号仅为示例，执行时先检查是否占用；不要改现有论文ID或自动重用有不同任务内容的批次目录。

## 参数表

| 参数 | 含义/默认 |
|---|---|
| `batchId` | 稳定批次号；未指定时使用下一个未占用编号 |
| `collectionId` / `collectionName` | 入站阅读集合；稳定ID、可读名称，不复用有不同含义的旧集合 |
| `limit` | 本批最多处理多少新论文；默认10，建议长任务分小批保存 |
| `scope` | 领域、基准年份、会议/来源、纳入范围、补充范围及排除条件；沿用时读实际计划 |
| `candidates` | 文件、链接或ID列表；空时须有发现论文的授权才检索 |
| `depth` | 默认abstract；fulltext先做独立研究材料，当前导入器尚需来源适配 |
| `diagrams` | 默认supported-only：有依据且有助理解才做，不要求每篇强行配图 |
| `mode` | prepare（默认）或import（本地合并） |
| `publish` | 默认false；true还须用户明确授权推送与部署 |
| `makeDefault` | 仅保留兼容元数据；页面统一全库，日常设false |
| `outputDir` | 相对于项目的目录；默认 `data/incoming/<batchId>/` |

领域和年份只写在任务参数/JSON中，不新增页面硬编码。跨年份的任务可按基准年份分批；各paper.year保留实际发表年份，scope.description明确边界。

## 示例一：接着做20篇，先不合并

```text
请执行 docs/ingestion/02-批量入库主提示词.md，遵循同目录01-入库标准.md。
项目根目录：D:/Coding/Git/myfile/arx/paper-aisle。
batchId：选择下一个未占用编号。
collectionId：由本批batchId生成一个稳定的新集合ID；collectionName：Agent 第二批泛读。
limit=20，depth=abstract，diagrams=supported-only。
scope：沿用已明确的Stage 01 Agent研究计划与现有Q目录，不自行扩大范围。
candidates：优先我附上的清单；未提供时允许检索原始来源补充。
mode=prepare，publish=false，makeDefault=false。
先去重，只制作尚未收录的新工作；轨道未知不阻止泛读。
每篇完成保存，交付research/guides/preview/checks/checkpoint，不修改在线数据。
```

“沿用计划”只适用于能实际读到该计划的会话。在其他工具中需要附上计划或直接写出范围，不能依赖另一个聊天的隐含记忆。

## 示例二：生成并合并到本地，暂不发布

```text
请按 docs/ingestion/02-批量入库主提示词.md，处理我提供的候选，最多15篇。
scope：按本次附带的范围说明；沿用现有Q目录，ID先查重。
batchId：下一个未占用编号；collectionName：本周阅读。
depth=abstract，diagrams=supported-only，mode=import，publish=false，makeDefault=true。
允许在schema/语义检查通过后更新本地data输入、追加导入配置并运行转换器。
保留旧批次、旧论文、datasetId及用户原有改动，运行生产验证和相关界面检查。
不要提交、推送或部署，交付变更报告和验收结果。
```

## 示例三：已做好批次，授权验收后发布

```text
请按 docs/ingestion/02-批量入库主提示词.md 的import流程，
接入 data/incoming/【实际批次号】/ 中的已完成批次。
mode=import，makeDefault=true，publish=true。
我授权在全部校验及本地验收通过后，仅提交本批相关改动并推送当前网站仓库的main，
触发既有GitHub—Vercel部署；不要推送无关改动。
不要重新采集已完成论文或生成新一批；保持原datasetId和论文ID。
报告实际提交号与部署检查结果。任何关键检查失败就保留进度、不发布。
```

## 当前import配置结构

这是结构说明，不可用它整体覆盖真实配置。将下面的对象**追加**到原 `batches` 数组，其他旧条目、legacyCollection、默认集合按授权保留。

```json
{
  "path": "data/batches/batch-002.research.json",
  "guidesPath": "data/guides/batch-002.json",
  "collection": {
    "id": "agent-stage01-batch-002",
    "name": "Agent 第二批泛读",
    "description": "按研究问题连续泛读；具体成员由本批可读数据生成。"
  }
}
```

guidesPath是导入文件名，不要求与incoming下文件名相同。即便没有图，仍为每篇准备headline/kind；没有任何guide时可提供合法空对象 `{}`，并报告内容缺口。

已入库同一论文需要补充时，使用04中的“更新”任务，保留唯一归属批次；不要把相同paper.id放到第二个已配置批次。

## 输入输出提醒

调研JSON与网站JSON不是同一种格式。新聊天至少提供主提示词、标准、两份输入schema、研究范围、现有Q目录和去重清单；要本地合并时还提供完整项目访问。未附文件/未授权工具时，不应让AI承诺“已经入库上线”。

日常推荐使用05中的10篇一条指令；本页20篇示例仅是可选参数，不是默认。先续跑已有未完成批次，不因默认递增编号遗失任务。

页面不再展示集合/批次切换。上面的旧参数仍可解析，但不改变页面浏览范围；批次结构只用于后台制作与追溯。
