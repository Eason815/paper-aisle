# Paper Aisle 批量入库提示词包

版本：1.0；日期：2026-10-23。适配当前静态网站与 `scripts/import-research.mjs`。本包规定内容生产与校验，不自动采集、调用模型或发布网站。

## 下次怎么用

在能读取本项目的聊天中，直接发送：

```text
请按 paper-aisle/docs/ingestion/02-批量入库主提示词.md 和 01-入库标准.md，
为 Paper Aisle 制作下一批最多 20 篇 Agent 论文。
沿用现有研究范围、问题目录和稳定 ID，跳过已经收录的同一工作。
batchId 使用下一个未占用的批次号，depth=abstract，mode=prepare。
优先使用我提供的候选；没有候选时从原始来源检索。
为适合的论文制作可点击概念图的数据，不为了凑图编造机制。
保存批次文件、预览、校验报告和续跑进度；本次不合并网站、不推送部署。
```

这不是固定20篇或固定Agent范围的系统限制；本次数量、领域、会议、年份、候选来源均可改。完整参数与“生成后合并”的调用见 [03-任务参数与调用示例.md](03-任务参数与调用示例.md)。

在其他聊天或工具中，提供主提示词、标准、两份输入 schema，以及当前问题目录与去重清单。模型无法读取本地路径时需要实际附上文件，不能仅粘贴路径。涉及网站合并时，还必须提供实际网站 schema、现有公开库、导入配置和转换器。

## 默认工作方式

1. 从原始页面/用户提供的原文制作批次，保留证据；未知机构、轨道、展示形式不强行补全。
2. 每篇一条主记录、一份中文导读；有实际结构且有助理解时再加图解。
3. 完成结构、语义、重复及证据检查；输出可导入/跳过/冲突清单。
4. 用户指定 `mode=import` 才合并到本地网站，保留 `datasetId`、历史论文及所有现有批次配置。
5. 用户明确允许发布，且本地验收通过后，才推送触发 Vercel。普通“做一批”不等于发布。

轨道未知与未人工确认不阻止进入泛读库；正式会议统计与泛读可见性分开。AI 整理不等于用户已读，个人收藏、状态、标签、便签一律不写入公共批次。

## 验证边界

Schema 能检查字段与格式，不能证明事实正确；证据引用存在，也不等于证据真的支持该结论。入库时必须实际打开/读取材料并进行语义检查。运行过什么就报告什么，不能用“AI自查”冒充浏览器验收或机器校验。

本包是可复用的指令与数据契约，不是已经实现的全自动采集器。首批的 `validate_and_render.py` 含固定10篇及入库前旧库假设，不能直接当作后续通用校验器。后续依照04中的检查项使用实际schema校验工具，并按当批数量、现有库与转换器检查。

本版已以现有10条研究记录、10份导读及3张图解检查契约兼容，6类无效输入被拒绝；网站22篇数据的schema与导入预览仍通过且无新增/更新。本次没有重新核读论文来源，也没有运行新一批内容生成或发布；这些结果不代表未来AI输出可免检。

本包采用明确任务、分隔材料、结构化输出与代表性检查的写法，参考 [OpenAI 官方提示词指导](https://developers.openai.com/api/docs/guides/prompt-engineering)。具体论文标准及当前导入限制来自本项目，不是 OpenAI 的领域标准。
